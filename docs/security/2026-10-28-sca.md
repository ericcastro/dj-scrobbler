# OSV remediation — 2026-10-28

OSV-Scanner 2.6.0 (`osv-scalibr` 0.5.2) scanned the project's `package-lock.json`. The original 0.7.0 lockfile produced **77 package/advisory findings**, representing **65 unique advisories across 14 affected package versions**. The updated 0.7.1 lockfile produces **zero findings**, with exit status 0. No ignore configuration, vulnerability suppressions, or dependency overrides were added.

Electron 43 retains macOS 12 compatibility while addressing the reported Electron advisories. Electron 44 and later require macOS 13; see [Electron's breaking changes](https://www.electronjs.org/docs/latest/breaking-changes). The updated Electron package requires Node.js 22.12 or newer and explicit runtime installation, so the project declares that engine requirement, runs `install-electron` after installation, and tests Node.js 22 and 24 in CI.

The packaging upgrade includes the upstream [AppImage search-path fix](https://github.com/electron-userland/electron-builder/security/advisories/GHSA-7g7r-gx96-252g), and the updater upgrade includes the [cross-origin credential redirect fix](https://github.com/electron-userland/electron-builder/security/advisories/GHSA-p2f4-r6v6-j797).

## Reproduction and scope

```sh
npm ci
osv-scanner scan .
npm test
npm run check:release
npm run test:media
```

The scan discovers the root npm lockfile and respects the repository's ignore rules. It does not establish the absence of vulnerabilities in ignored build output, FFmpeg source archives, downloaded native executables, operating-system frameworks, or remote services. Casting remains experimental and macOS-only; Windows/Linux casting support is coming soon.

CI runs the official OSV reusable workflow pinned to its v2.6.0 commit. Release builds depend on that scan succeeding; scanner failures and vulnerability findings block publication.
